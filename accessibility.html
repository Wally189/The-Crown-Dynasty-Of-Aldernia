Accessibility

The front door should work for more than one kind of visitor.

This founding edition is built with semantic HTML, keyboard-visible focus, skip links, responsive layouts, reduced-motion handling and text-first content. The design target is WCAG 2.2 AA, used here as a practical quality benchmark.

What we have designed for

Keyboard navigation; readable contrast; meaningful heading order; responsive text and layouts; no colour-only status meaning; reduced-motion preferences; descriptive page titles; no auto-playing media; and content that remains useful when JavaScript fails.

How releases are checked

Material releases use structural regression plus served-site browser checks at mobile and desktop sizes, keyboard-focus checks, reduced-motion checks and automated WCAG-tagged testing. Automated testing is not proof of universal accessibility: as the service grows in consequence, representative assistive-technology and disabled-user testing remains necessary.

Public standard references

UK public-sector guidance points to WCAG 2.2 AA and emphasises considering accessibility from the beginning of digital-service design. Aldernia adopts that standard as its current public design benchmark even though the fictional country is not itself a real public authority.
